# Cortex-M3 / Thumb-2 Bare-Metal ISA Readiness Audit

## Executive Summary
TinyCpuSim implements an initial subset of Thumb-1 and Thumb-2 (MOVW, MOVT, BL, ALU). However, standard bare-metal C code generated by GCC (`-mcpu=cortex-m3 -mthumb -O2`) fails due to missing stack adjustments, extensions, divide, barriers, and 32-bit branches. Additionally, Vector Table hardware MSP initialization and runtime C startup (`.data` copy / `.bss` zeroing) are missing.

## 2. Loader & Startup Readiness Findings

1. **Vector Table Initial MSP Unhandled by Loader**:
   - ARM Cortex-M hardware loads `SP` (MSP) from vector `0x00000000` (`_svectors[0]`) and `PC` from vector `0x00000004` on reset.
   - `Loader::load_elf` ([loader.hpp#L102-L104](file:///home/kw/workspace/TinyCpuSim/.worker-tree/include/tinyarmsim/loader.hpp#L102-L104)) only reads `e_entry` into `PC`; `SP` remains `0`.
   - `ArchitecturalState` ([state.hpp#L28-L31](file:///home/kw/workspace/TinyCpuSim/.worker-tree/include/tinyarmsim/state.hpp#L28-L31)) initializes all registers to `0`.
2. **Missing C Runtime Initialization in Startup**:
   - `firmware/bsp/startup.s` ([startup.s#L34-L39](file:///home/kw/workspace/TinyCpuSim/.worker-tree/firmware/bsp/startup.s#L34-L39)) loads `sp`, then jumps directly to `main`.
   - It does not copy `.data` from flash (`_etext` to `_sdata`..`_edata`), nor zero `.bss` (`_sbss`..`_ebss`).
   - `Loader::load_elf` ([loader.hpp#L96-L98](file:///home/kw/workspace/TinyCpuSim/.worker-tree/include/tinyarmsim/loader.hpp#L96-L98)) zero-fills BSS when loading ELF segments, but flash-to-RAM data relocation is not performed.
