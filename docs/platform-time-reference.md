# Platform time reference slice

`TimeScheduler` is a single-host-thread functional reference. Time is an unsigned 64-bit integer in abstract ticks. One successful interpreter step costs one tick, including exception entry; this is a functional model, not hardware cycles. An interpreter step is indivisible: events at a tick run before the next step, including at the requested deadline. There is no deadline overshoot. Progress counts successful steps, not requested quantum or retired instructions. A faulting step consumes no tick; side effects made by the interpreter before a fault are not rolled back. Software interrupt exceptions are reported as halt; other `CpuFaultException`s are reported as fault. Other exceptions propagate. WFI currently behaves as the interpreter implements it, without a wait stop reason.

The deadline is absolute and cannot precede current time. Quantum must be positive; this reference checks events at every boundary regardless of quantum. At each time, device events precede IRQ events; sequence order resolves ties within a phase. A callback cannot schedule an earlier phase at the current time, or an event in the past. More than 10,000 same-time callbacks in one dispatch is diagnosed as nonprogress. Event callback ownership and cancellation are the caller's responsibility.

`ClockConversion(numerator, denominator)` converts input units to output ticks using floor division and retains the remainder between calls. Both ratio terms must be positive. It checks the intermediate multiplication and addition, rejecting overflow even if division could yield a representable result; failure leaves the remainder unchanged.

The interpreter-backed reference test uses a passive MMIO register and a scheduled NVIC interrupt. Interpreter steps still invoke legacy bus ticking. Autonomous scheduler-driven timers, WFI suspension, MMIO traces, cancellation/reset ownership, multicore coordination, and migration of existing platforms are deferred. No cycle-accuracy or platform-wide conformance is claimed.
